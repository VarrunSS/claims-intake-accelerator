## Decision rules

1. **Candidates** are model configurations that were actually run (model and prompt version). The heuristic baseline is the reference, not a candidate. A registry entry that has not been run is not a candidate. FAKE rows are considered only when no real model was run, and then the pick is labelled a demonstration.
2. **Gate.** A candidate must pass every threshold in the gate file (by default `evals/model-thresholds.json`): field F1 and per-field F1, issue and finding precision and recall, route accuracy, citation groundedness, silent-error rate, no pipeline errors, a malformed-output rate and a p95 latency ceiling. A metric that was not measured fails its threshold.
3. **Cost.** A candidate must have a measurable cost per claim (the model reported token usage and the registry has a price).
4. **Pick** the cheapest passing candidate by cost per claim.
5. **Ties** (costs within £0.0001 per claim) go to the lower p95 latency per claim (within 1 ms counts as equal), then the lower malformed-output rate, then the label in alphabetical order.
6. **No pick.** If no candidate passes, there is no recommendation: the report names the candidates and the gates they failed.
7. **Caveats are attached, not applied.** If the chosen price is marked verify-before-use the recommendation says so. The rules never use judgement about the text of an answer.
